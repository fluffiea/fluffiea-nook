# 📂 Linux 目录规范

## 核心原则：各归其位

Linux 文件系统有一套标准（FHS），规定不同类型的数据放在哪里：

| 路径 | 放什么 | 适合举例 |
|:----|:-------|:---------|
| `/opt/` | **第三方软件包** | Immich、Docker Compose 项目、手动安装的应用 |
| `/srv/` | **服务数据** | Web 站点文件、FTP 共享、Git 仓库裸目录 |
| `/var/lib/` | **系统包管理器数据** | apt 安装的软件状态、数据库数据 |
| `/var/log/` | **日志文件** | 系统日志、应用日志 |
| `/etc/` | **系统配置文件** | nginx 配置、系统服务配置 |
| `/usr/local/` | **本地编译安装的软件** | `make install` 装的东西 |
| `/home/` | **用户个人文件** | 文档、下载、项目代码 |

## `/opt/` 最常用

对个人开发者来说，`/opt/` 是最常用的目录。所有**自己手动部署的服务**都可以放这里：

```
/opt/
├── immich/          # Immich 相册（docker-compose.yml + 数据）
├── nginx/           # 手动安的 nginx
└── frp/             # 内网穿透客户端/服务端
```

优势：不乱、互不影响、一眼看出是手动装的。

## 常见误区

| ❌ 错误做法 | 说明 |
|:-----------|:-----|
| 放 `/home/你/` 下 | 跟用户目录耦合太紧，别人访问不方便，也不合规范 |
| 放 `/var/lib/` 下 | `var/lib` 是给包管理器用的，手动创建的文件容易跟系统文件混淆 |
| 放 `/root/` 下 | root 用户的家目录，非 root 用户操作不方便 |

## 总结

- **自己部署的服务** → `/opt/<项目名>/`
- **系统服务的数据** → `/srv/<服务名>/`
- **系统包管理器管的** → 别碰，留给 apt
- **用户自己的项目** → `/home/你/`
